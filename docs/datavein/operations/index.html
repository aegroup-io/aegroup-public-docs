Evidence discipline

Stable IDs for every observation and claim (EV-*, CL-*); a seven-level evidence priority from consumer-visible data down to inference; contradictions preserved, never collapsed. Absence from a bounded queue peek is not emptiness; API acceptance is not proof that data changed.

Authority + safety — typed grants, fail-closed boundaries

Resolve authority before interpreting state or mutating anything. Conflicting signals produce authority-conflict, never a guessed winner.

Environment authority

Production is the sole ordinary scheduler/extractor authority; target_environment is a production-only downward override — dev and test can never resolve production from it. Historical runbooks are evidence, not authority.

Production grants

An explicit execute or recover request becomes finite typed grants — no per-step approvals, no reflexive tickets. Mutations stop on a new system or cohort, an expired grant, destructive scope, or any security or data-integrity signal.

Code vs. runtime

Runtime recovery may act in production; software changes never do. Code flows through dev, a PR, human review, release, and production verification — the repository delivery harness — then the operation resumes and retests the original condition.

Redaction boundary

Credentials, tokens, private payloads, and personal data never enter the operation package, T-Base, a prompt, or an issue. Every evidence item is marked none · masked · hashed · metadata-only.

State machines, kept separate

Nine operation states with evidence-gated transitions; eleven data-execution states from eligible to validated. "Delivery unknown" is distinct from "not delivered"; attempts are never collapsed into one generic run.

Closeout + learning — the loop that stays honest

Only resolved and justified mitigated states may claim service health. "Ticket opened" never means "incident resolved."

Completion doctrine

A terminal receipt needs the exact cohort, runtime completion evidence, and data correctness or freshness at the consumer boundary — plus regression and collateral checks.

Independent validation

The validator is not the mutation author. Seven minimum acceptance checks for any runtime change; read-only modes validate the question answered, never an invented canary.

External ownership

Eight handoff types, one accountable owner, an executable acceptance test, and a dedupe search before any new issue. When the owner acts, a new operation verifies the unblock.

Gated self-improvement

The pack never rewrites itself mid-operation. Changes ride an eight-step ladder — regression fixture, adversarial and held-out evals, review, version bump — and are rejected if they weaken evidence, redaction, or authority.
